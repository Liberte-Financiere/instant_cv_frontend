[2026-06-21] — CRM & HQ Ops KPIs (V2)

What changed:
- Added `isBanned` boolean to the `User` Prisma model.
- Upgraded the `/dashboard/hq-ops/page.tsx` index to a Server Component to display real-time global KPIs (Total Users, Daily Signups, Credits Consumed, Credits Distributed).
- Transformed the `/dashboard/hq-ops/credits` page into a fully-fledged CRM that now displays user roles, active/banned status, and allows admins to ban/unban users directly from the UI.
- Created `/api/admin/users/ban` route to handle status toggle securely.

Why:
- To give the admin a high-level overview of the platform's health (KPIs).
- To provide a quick action to stop fraudulent or abusive accounts from consuming API resources (Ban mechanism) without creating a redundant "Users" page.

Files affected:
- prisma/schema.prisma — Added isBanned field.
- app/dashboard/hq-ops/page.tsx — Refactored to Server Component, added KPI section.
- app/dashboard/hq-ops/credits/page.tsx — Added Role, Status columns and Ban toggle.
- app/api/admin/users/credits/route.ts — Returned isBanned and role fields.
- app/api/admin/users/ban/route.ts — Created new route for banning.

Notes for review:
- Users are banned at the API boundary/SignIn boundary, not actively booted from Edge Middleware, because checking the DB on every single Edge request via JWTs would cause massive latency.
