[2026-08-21] — Fix B2B Admin Auth and UI Cleanup

What changed:
- Switched all B2B API endpoints to fetch user data directly from the DB instead of relying on the JWT session.
- Excluded SCHOOL_ADMIN users from the B2B students list.
- Added explicit protection to prevent detaching SCHOOL_ADMIN users via the students API.
- Completely removed the Sparkles (✨) icon from the codebase.
- Replaced Sparkles with Wand2 for AI actions and Coins for credit/billing actions.

Why:
- JWT tokens can contain stale data (e.g. `schoolId` being null) if an admin's rights are updated post-login, causing random 403 Forbidden errors. Fetching from the DB ensures accurate real-time authorization.
- Admins were erroneously appearing in the students list and could accidentally delete themselves, nullifying their own `schoolId` and breaking their admin access.
- The UI needed to be cleaned up and the use of the Sparkles icon was deemed unprofessional and distracting. 

Files affected:
- app/api/b2b/school-admin/invitations/route.ts — Fetch user from DB to fix 403.
- app/api/b2b/school-admin/invitations/[id]/revoke/route.ts — Fetch user from DB to fix 403.
- app/api/b2b/school-admin/students/route.ts — Fetch user from DB, exclude admins from list, block admin deletion.
- app/api/b2b/school-admin/stats/route.ts — Fetch user from DB to fix 403.
- (Multiple UI files) — Replaced Sparkles icon with Wand2/Coins across the codebase.

Breaking changes:
- None.

Notes for review:
- The `schoolId` bug caused some admins to have `schoolId: null` in production. This was manually fixed via SQL for the concerned user.
- The Sparkles replacement touched many components (Toolbar, Modals, Pricing, Sidebar). Everything was verified to be visually consistent.
