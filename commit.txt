[2026-08-24] — Feature: Dynamic file requirements for candidate applications

What changed:
- Updated the ApplyPage (`app/jobs/[id]/apply/page.tsx`) to dynamically display file upload fields based on the `job.requestedFiles` array (CV, Cover Letter, Portfolio, Diploma).
- Implemented parallel file uploading to Cloudinary via `Promise.all` in the application form.
- Added strict backend validation in `app/api/jobs/[id]/apply/route.ts` to reject applications missing files requested by the recruiter.
- Fixed a React reconciliation bug on the recruiter job creation wizard that caused ghost clicks (auto-submit) by adding `key` props to the navigation buttons.
- Redesigned the Recruiter Analytics page (`app/recruiter/analytics/page.tsx`) with a "Clean SaaS" light theme and shimmer animations.
- Added unit tests for the application API route (`__tests__/api/jobs/apply.test.ts`) to verify dynamic file validation logic.

Why:
- The recruiter needs the ability to define which files are mandatory for a specific job offer (e.g. asking for a Portfolio for a design job). 
- The application form must adapt to these requirements and ensure the candidate cannot bypass them, both on the frontend and backend.
- The analytics dashboard required a visual overhaul to match the professional, light-themed aesthetic of the rest of the application.

Files affected:
- prisma/schema.prisma — Added requestedFiles array to JobOffer and specific file URL fields to JobApplication.
- app/api/recruiter/jobs/route.ts — Added requestedFiles validation when creating a job.

- app/recruiter/jobs/page.tsx — Added real-time search filtering.
- app/recruiter/analytics/page.tsx — Redesigned the analytics dashboard.
- app/api/jobs/[id]/apply/route.ts — Added backend validation for required files and fallback values for Prisma.
- app/jobs/[id]/apply/page.tsx — Refactored to fetch job requirements and dynamically display upload components.
