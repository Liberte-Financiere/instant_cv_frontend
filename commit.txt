[2026-08-26] — FEAT: Job Offer Edit & Quota Management

What changed:
- Extracted job creation form into a reusable `JobForm` component.
- Implemented `/recruiter/jobs/[id]/edit` page with pre-filled data.
- Updated `PATCH /api/recruiter/jobs/[id]` to fully support all schema fields including `NATIVE` apply method, `expiresAt`, `maxApplications`, and `requestedFiles`.
- Transformed `null` values for `applyUrlOrMail` into empty strings to prevent Prisma validation errors.
- Enhanced recruiter jobs dashboard (`app/recruiter/jobs/page.tsx`) with a segmented control UI for actions (View, Edit, Toggle, Delete).
- Implemented auto-close logic in `POST /api/jobs/[id]/apply`: jobs automatically transition to `CLOSED` status once the `maxApplications` quota is reached.
- Added comprehensive Vitest unit tests for the job edit API route, verifying authentication, authorization, and Zod validation.

Why:
- Recruiters needed the ability to fix typos or adjust requirements on published job offers.
- Centralizing the form logic (DRY) simplifies future maintenance for both creation and editing flows.
- Automatically closing jobs upon reaching the applicant quota prevents misleading UI states and ensures no rogue applications can bypass the limit.

- app/recruiter/jobs/page.tsx — Updated action buttons to premium segmented UI.
- app/api/jobs/[id]/apply/route.ts — Added logic to set job status to `CLOSED` when quota is hit.
