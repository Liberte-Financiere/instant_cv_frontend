[2026-08-26] — FEAT: Smart Auto-fill (IA Groq) & 4-Step Job Wizard

What changed:
- Refactored `JobForm.tsx` from a 3-step to a 4-step wizard.
- Introduced the "Smart Auto-fill" feature in Step 1 for external job postings (URL/EMAIL).
- Implemented file upload for PDFs, delegating text extraction to the existing `POST /api/utils/parse-pdf` route.
- Created `POST /api/recruiter/jobs/parse` to process raw job descriptions via the official `@ai-sdk/groq` provider.
- Used Zod schema with `generateObject` to strictly extract `title`, `company`, `location`, `type`, `salary`, `applyUrlOrMail`, `requirements`, and `description`.
- Tuned the AI prompt to ensure contextual information (timelines, specific application steps, conditions) is appended to the `description` field rather than discarded.
- Integrated auto-progression in the UI: once AI parsing succeeds, the form auto-advances to Step 2 with fields magically pre-filled.

Why:
- Recruiters posting external jobs often copy-paste from WhatsApp or LinkedIn. Filling fields manually is tedious.
- Groq's high-speed inference allows for near-instant JSON extraction, drastically reducing the friction of publishing a job offer.
- Relying on the official Groq SDK avoids compatibility issues with OpenRouter aliases, ensuring stable parsing.

Files affected:
- components/jobs/JobForm.tsx — [MODIFY] Refactored into a 4-step wizard with the new AI text/PDF upload zone.
- app/api/recruiter/jobs/parse/route.ts — [NEW] Groq-powered API route for JSON extraction.

Breaking changes:
- None.

Notes for review:
- The AI parsing is highly dependent on the model configured in `APP_CONFIG.ai.models.groqJobReformulation`. Ensure this maps to a valid Groq model string (e.g., `llama-3.1-70b-versatile`) in production.
- If the AI fails or the raw text is unparseable, the UI gracefully falls back, allowing manual entry.
